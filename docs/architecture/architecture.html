System Prerequisites & Setup Requirements
Developer tools, container runtimes, and step-by-step initialization sequence

Local dev runs the full Supabase stack via the Supabase CLI (Docker-backed) plus a Vite dev server for the client. No separate Deno install is needed — the CLI bundles the Edge Runtime.

🛠️ Required Tools & Runtimes
⚡
Docker Desktop Required
Version any recent
Backs the local Supabase stack (Postgres, PostgREST, Auth, Storage, Realtime, Edge Runtime, Studio, Mailpit).
⚡
Supabase CLI Required
Version latest
Runs/manages the local stack (`supabase start`), applies migrations, serves Edge Functions.
⚡
Node.js Required
Version >= 20
Builds and runs the web/ Vite PWA client.
🚀 Setup & Execution Pipeline
1
Configure environment
supabase/functions/.env is gitignored and holds real vendor keys (Anthropic, ElevenLabs, Cohere) — copy from a checkout that has them if one exists; a fresh git worktree never carries it.
cp .env.example .env && cp supabase/functions/.env.example supabase/functions/.env
2
Start the local Supabase stack
Boots Postgres, PostgREST, Auth, Storage, Realtime, the Edge Runtime, Studio, and Mailpit on the ports remapped in supabase/config.toml (54421-54429).
supabase start
3
Verify the schema
Runs 12 live assertions (RLS, normalization, idempotency, search). Expect 'ALL SCHEMA CHECKS PASSED'.
docker exec -i supabase_db_Second_Brain psql -U postgres -d postgres -v ON_ERROR_STOP=1 < supabase/tests/verify.sql
4
Install and verify the web client
verify = typecheck + RTL guard (check-rtl.mjs) + vitest (21 tests) + production build.
cd web && npm install && npm run verify
5
Run the dev server
Vite dev server for the PWA client.
npm run dev

notes

POST
/🔑

GET
/🔑

POST
/audio-url🔑
Signed Storage upload URL for a voice note, scoped to <user_id>/.
🎤
transcribe
/functions/v1/transcribe
Stage 1 of the AI pipeline: audio -> raw_text + confidence via ElevenLabs Scribe. Idempotent on existing raw_text.
POST
/🔑
Transcribe a voice note's audio. Returns cached raw_text on retry, no repeat ASR call.
✨
enrich
/functions/v1/enrich
Stages 3-5: Anthropic Opus 5 enrichment (summary/category/tags/priority), Cohere embedding, SQL nearest-neighbour relations. Idempotent on (note, language, prompt_version); force:true overrides.
POST
/🔑
Run enrichment + embedding + relation-detection for a note.
🔍
search
/functions/v1/search
Hybrid / semantic / lexical retrieval. lexical mode skips the embedding call entirely.
POST
/🔑
Search notes: mode = hybrid | semantic | lexical, optional category filter.
📅
digest
/functions/v1/digest
Weekly AI review. Two-phase: enqueue (submit Anthropic Batch job) / collect (poll and store result). Cron-triggered via pg_cron + pg_net, Vault-stored secrets.
POST
/🔑
{action: "enqueue" | "collect"} — normally invoked by the digest-enqueue/digest-collect pg_cron schedules, not directly by the client.
📦
export
/functions/v1/export
Full data export. Runs entirely under the caller's own client (RLS) — no user_id filter anywhere in the function; RLS is the reason no other user's data is reachable.
GET
/🔑
Every note, enrichment, and tag the caller owns. Includes raw_text and archived notes; not paginated.
⚠️
delete-account
/functions/v1/delete-account
Irreversible account deletion. Requires the caller to type back their own email as confirmation. Deletes Storage audio objects first, then auth.admin.deleteUser() cascades through every FK-referencing table.
POST
/🔑
{confirm_email} — 400 confirmation_mismatch if it doesn't match the authenticated session's own email.
🧹
sweep
/functions/v1/sweep
Not client-facing. Invoked by the sweep-worker pg_cron job (*/5 * * * *) via pg_net, using Vault-stored URL/service-role secrets. Unsticks notes stranded in transcribing/enriching, retries stale queued notes (capped at 5 attempts via ai_jobs before marking failed), backfills missing embeddings, and deletes expired audio from Storage.
POST
/🔑
Service-role only. Shares pipeline logic with enrich/transcribe via _shared/pipeline.ts.

⚡ Hybrid lexical + semantic search (Reciprocal Rank Fusion, k=60)
search • public.search_notes(p_query, p_language, p_embedding, p_mode, p_categories, p_limit)

Purpose: SECURITY INVOKER so the caller's own RLS filters results (a SECURITY DEFINER version would have to hand-reimplement ownership filtering). Fetches top-200 candidates per arm (lexical ts_rank_cd, semantic cosine distance), fuses by RRF since BM25 ranks and cosine distances aren't on comparable scales. LEFT JOINs note_enrichments so an unenriched note is still findable.
File: supabase/migrations/20260801000500_rpc.sql | Tables: notes note_embeddings note_enrichments

Consuming Endpoints: POST /functions/v1/search  
with lexical as ( select id, row_number() over (order by ts_rank_cd(search_vector, tsq) desc) as rnk from notes where mode in ('hybrid','lexical') and search_vector @@ tsq and status='ready' and archived_at is null limit 200 ), semantic as ( select note_id as id, row_number() over (order by embedding <=> p_embedding) as rnk from note_embeddings where mode in ('hybrid','semantic') and language = p_language limit 200 ), fused as ( select coalesce(l.id,s.id) as id, coalesce(1.0/(60+l.rnk),0) + coalesce(1.0/(60+s.rnk),0) as score from lexical l full outer join semantic s on s.id = l.id ) select n.*, e.title, e.summary from fused f join notes n on n.id = f.id left join note_enrichments e on e.note_id = n.id and e.language = p_language order by f.score desc limit p_limit;

⚡ Nearest-neighbour note relation detection
enrich • public.relate_note(p_user_id, p_note_id, p_language, p_threshold=0.78, p_limit=5)

Purpose: No model call — pure SQL cosine similarity against the note's own embedding, same model, same user, same language. Inserts up to 5 relations above a 0.78 similarity threshold.
File: supabase/migrations/20260801000500_rpc.sql | Tables: note_embeddings note_relations

Consuming Endpoints: POST /functions/v1/enrich  
with src as (select embedding, model from note_embeddings where note_id=$note_id and language=$language limit 1), nearest as (select distinct on (e.note_id) e.note_id, 1-(e.embedding <=> (select embedding from src)) as similarity from note_embeddings e join notes n on n.id=e.note_id where e.user_id=$user_id and e.note_id<>$note_id and e.language=$language and e.model=(select model from src) and n.archived_at is null order by e.note_id, e.embedding <=> (select embedding from src)), picked as (select * from nearest where similarity >= $threshold order by similarity desc limit $limit) insert into note_relations (from_note_id, to_note_id, user_id, kind, score) select $note_id, note_id, $user_id, 'similar', similarity from picked on conflict (from_note_id, to_note_id, kind) do update set score = excluded.score;
