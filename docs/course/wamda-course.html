كورس تعليمي كامل: مشروع "ومضة" من الكود الحقيقي

الكورس ده مبني بالكامل على قراءة كود المشروع الفعلي — مفيش أمثلة وهمية. كل Endpoint، كل جدول، كل سطر كود معروض هنا منسوخ من الملفات نفسها. الهدف إنك تفهم إزاي مشروع حقيقي (real-world) اتبنى، مش بس تتعلم مفاهيم عامة.

🧭
إزاي تستخدم الكورس ده

استخدم القائمة الجانبية للتنقل بين الفصول التسعة. كل فصل مستقل، تقدر تبدأ منه على طول، بس الترتيب هيفيدك لو ده أول مرة تشوف المشروع. كل الأكواد جوه صناديق سوداء منسّقة — مسارات الملفات مكتوبة فوق كل صندوق كود.

عن مشروع ومضة في سطرين

ومضة تطبيق "دماغ ثاني" (second brain) لالتقاط الأفكار بسرعة — بالصوت أو بالكتابة — موجّه لمستخدم يفكّر بالعربي وعنده ADHD. الفكرة الأساسية: الوقت بين ما تقرر توثّق فكرة وبين ما تبقى محفوظة فعليًا هو أهم رقم في المنتج كله. بعد كده الذكاء الاصطناعي بيصنّف الملاحظة، يلخّصها، ويقترح إجراء (مهمة، موعد، إلخ) — وده ممكن ياخد وقته.

01 · Docker

Docker

خبر مهم قبل ما نبدأ: المشروع ده معندوش Dockerfile ولا docker-compose.yml مكتوب بإيدينا. ده مش نقص — ده قرار. هنشرح ليه، وهنشرح Docker من الصفر عشان تفهم اللي بيحصل تحت السطح لما تشغّل supabase start.

ايه هو Docker أصلًا؟

تخيّل إنك عايز تبعت تطبيق لزميلك يشغّله عنده. عندك مشكلة كلاسيكية: "شغّال عندي، مش شغّال عنده" — فرق في نسخة Node، أو مكتبة ناقصة، أو نظام تشغيل مختلف. Docker بيحل المشكلة دي بإنه يحزّم التطبيق مع كل حاجة محتاجها (نظام تشغيل مصغّر، المكتبات، الإعدادات) في وحدة واحدة اسمها Container — تشتغل بنفس الشكل بالظبط على أي جهاز فيه Docker.

الفايدة العملية هنا في مشروع ومضة: بدل ما تثبّت Postgres، ونظام Auth، وStorage، وDeno runtime، كل واحد لوحده على جهازك (ونتعامل مع مشاكل التوافق بينهم)، أداة Supabase CLI بتشغّلهم كلهم كـ Containers جاهزة ومضبوطة بالفعل.

الفرق بين Container و Image و Docker Compose

المصطلحيعني ايهمثال من ومضة

⚠️
الصراحة المطلوبة هنا

بحثت في المشروع كامل (git ls-files) ومفيش أي Dockerfile أو docker-compose.yml. الـ Docker الوحيد المستخدم هو اللي بتديره أداة Supabase CLI نفسها — هي اللي بتشغّل مجموعة Containers جاهزة (Postgres، PostgREST، GoTrue للـAuth، Storage API، Edge Runtime، Studio، Mailpit) عشان تحاكي مشروع Supabase حقيقي على جهازك، بدون ما تكتب أي إعداد Docker بنفسك.

تفعيل Docker على جهازك من الصفر

  1. ثبّت Docker Desktop

    حمّله من docker.com (Windows / Mac / Linux). هو اللي بيوفّر المحرّك اللي الـ Containers بتشتغل عليه.

  2. تأكد إنه شغّال

    terminalbash

    docker ps بيعرض الـ Containers الشغّالة دلوقتي. لو رجع لك جدول فاضي من غير خطأ، Docker شغّال تمام.

  3. ثبّت Supabase CLI

    terminalbash

    من جذر المشروعbash

02 · API

الـ API

كل الـ API عبارة عن 8 Edge Functions (كود Deno شغّال على سيرفر Supabase)، الأساس /functions/v1، والمصادقة عبر Supabase JWT في هيدر Authorization: Bearer.

البنية العامة (structure)

كل ملف index.ts جوه supabase/functions/<name>/ هو دالة واحدة Deno.serve(async (req) => {...}). الشكل العام ثابت في كل الـ functions تقريبًا:

الهيكل العام لأي edge functionts
Deno.serve(async (req) => {
  const pre = preflight(req);       // رد الـ CORS الأولي (OPTIONS)
  if (pre) return pre;

  let language = "ar";
  try {
    const supabase = userClient(req);        // عميل يتصرف بصلاحيات المستخدم صاحب الطلب
    const user = await authenticate(supabase); // تحقق من الـ JWT + جيب البروفايل
    // ... منطق الـ endpoint
    return json({ ... }, { language, direction });
  } catch (err) {
    return errorResponse(err, language);      // كل الأخطاء بتتحول لكود موحّد
  }
});

لغة الطلب (Language)

كل endpoint بياخد lang (query أو body) ويحترم هيدر Accept-Language. الترتيب: صريح ← إعداد المستخدم المحفوظ ← Accept-Language ← عربي افتراضيًا. وكل رد بيرجّع اللغة اللي اتخدم بها + الاتجاه (rtl/ltr) — العميل مايحتاجش يخمّن.

الـ Best Practices الفعلية المستخدمة في الكود ده

  • Keyset Pagination مش OFFSET في GET /notes: الـ cursor عبارة عن آخر client_created_at في الصفحة اللي فاتت، مش رقم صفحة. السبب موثّق في تعليق الكود نفسه: OFFSET بيعيد فحص ويرمي كل صف اتخطّاه، فصفحة 50 بتكلّف 50 ضعف صفحة 1.
  • Idempotency على كل مرحلة مكلّفة: /notes على client_id، /transcribe على وجود raw_text بالفعل، /enrich على (note, language, prompt_version). إعادة محاولة أبدًا متدفعش تاني.
  • أكواد أخطاء ثابتة، مش جُمل بشرية: كل خطأ بيرجع {error: {code: "..."}}؛ العميل هو اللي بيترجم الكود لجملة (مفصّل في فصل 6).
  • Rate Limiting قبل استدعاء أي مزوّد مدفوع: /enrich و/transcribe بيستدعوا enforceRateLimit() قبل ما يوصلوا لـ Anthropic/ElevenLabs.
  • فصل عميل المستخدم عن عميل الخدمة: القراءة اللي بتتأكد من ملكية الملاحظة بتحصل بعميل المستخدم (تحت RLS)؛ الكتابة اللي محتاجة تتجاوز RLS (زي كتابة نتيجة التصنيف) بتحصل بعميل خدمة منفصل (serviceClient()).
  • الـ Timeline بيسيب raw_text عمدًا: بيرجّع الملخّص بس، مش النص الكامل — الفرق بين رد 30KB و900KB على تمرير طويل.

عمق: الـ Edge Functions المشتركة (_shared/)

الملفات دي بيستوردها أكتر من function واحدة — عشان كده هي "مشتركة". لو غيّرت منطق فيها، بيتغيّر في كل حتة بتستخدمها مرة واحدة.

_shared/http.ts — الردود، الأخطاء، الـ CORS

ثلاث وظايف أساسية: corsHeaders()/preflight() للتعامل مع طلبات OPTIONS، json() لتغليف أي رد بشكل موحّد (بيضيف اللغة والاتجاه تلقائيًا)، وHttpError + errorResponse() لتحويل أي استثناء لرد JSON بكود ثابت بدل رسالة نصية قد تسرّب تفاصيل داخلية.

supabase/functions/_shared/http.tsts
export function errorResponse(err: unknown, language?: string): Response {
  if (err instanceof HttpError) {
    return json({ error: { code: err.code } }, { status: err.status, language });
  }
  // متسربش أبدًا رسالة داخلية للعميل — الـ stack traces بتحتوي
  // أسماء جداول، ومعرّفات، وأحيانًا بيانات صفوف كاملة.
  console.error("unhandled_error", err instanceof Error ? err.message : String(err));
  return json({ error: { code: "internal_error" } }, { status: 500, language });
}

_shared/language.ts — الحل الوحيد لتحديد اللغة

الملف ده هو "المفصل" اللي بيخلّي النظام قابل لدعم لغة تانية بسهولة. فيه SUPPORTED (سجل اللغات المفعّلة)، resolveLanguage() (يقرر لغة الطلب مرة واحدة)، وdetectLanguage() (كاشف لغة بسيط بيعتمد على نطاقات Unicode بدون أي نموذج ذكاء اصطناعي).

_shared/supabase.ts — نوعين من العملاء

web/src/data/outbox.ts — قلب الالتقاط الأوفلاين

مسؤول عن تخزين الملاحظات في IndexedDB (مش localStorage) قبل أي محاولة اتصال بالشبكة. السبب موثّق في الكود نفسه: localStorage متزامن (بيوقف الـ main thread وقت الكتابة) وبيخزّن نصوص بس؛ IndexedDB غير متزامن وبيخزّن Blob (تسجيل صوتي) كما هو.

web/src/data/outbox.tsts
export async function capture(input: {
  source: NoteSource; language: string; text?: string; audio?: Blob;
}): Promise<OutboxNote> {
  const start = performance.now();
  const database = await db();

  const note: OutboxNote = {
    // client_id بيتولّد هنا، أوفلاين — وده اللي بيخلّي الإعادة idempotent
    // على مستوى السيرفر. لو السيرفر هو اللي بيولّده، أي إعادة محاولة
    // لطلب لسه معلّق هتبقى ملاحظة مكررة.
    clientId: crypto.randomUUID(),
    source: input.source,
    language: input.language,
    capturedAt: new Date().toISOString(),
    attempts: 0,
    ...(input.text !== undefined ? { text: input.text } : {}),
    ...(input.audio !== undefined ? { audio: input.audio } : {}),
  };

  await database.put("outbox", note);   // <- هنا الملاحظة بقت "دائمة" فعليًا
  note.captureLatencyMs = Math.round(performance.now() - start);
  void database.put("outbox", note);    // كتابة تانية للقياس، مش منتظَرة عمدًا

  return note;
}

web/src/data/api.ts — طبقة الاتصال بالسيرفر

بيلفّ كل استدعاء supabase.functions.invoke() في دالة invoke<T>() واحدة بتضيف اللغة تلقائيًا وتحوّل أي خطأ لكود موحّد. أهم دالة فيه هي sync():

export async function sync(): Promise<{ synced: number; failures: SyncFailure[] }> {
  if (!navigator.onLine) return { synced: 0, failures: [] };

  const { data } = await supabase.auth.getSession();
  if (!data.session) return { synced: 0, failures: [] };  // بدون جلسة، ماتحاولش

  let synced = 0;
  const failures: SyncFailure[] = [];
  for (const note of await pending()) {   // بالترتيب، الأقدم أولًا — مش متوازي
    try {
      const serverId = await captureNote(note);
      if (note.source === "voice" && note.audio) {
        const { path, upload } = await requestAudioUrl(serverId, note.language, note.audio.type);
        await supabase.storage.from("audio").uploadToSignedUrl(path, upload.token, note.audio);
        await transcribe(serverId, note.language);
      }
      await enrich(serverId, note.language).catch(() => { /* فشل التصنيف مايفشلش المزامنة */ });
      await markSynced(note.clientId, serverId);
      synced += 1;
    } catch (err) {
      failures.push({ clientId: note.clientId, message: describeError(err) });
      await markAttempted(note.clientId);
    }
  }
  return { synced, failures };
}

04 · Supabase

Supabase

Supabase هي المنصة اللي بتوفّر: قاعدة بيانات Postgres حقيقية + REST API مولّد تلقائيًا فوقها + نظام Auth + تخزين ملفات + مكان لتشغيل كود سيرفر (Edge Functions) — كل ده في مكان واحد.

ليه Supabase بالذات؟

البديلالفرق عن Supabase هنا
Firebaseقاعدة بيانات NoSQL — المشروع محتاج بحث نصي عربي متقدّم (tsvector) وبحث متجهي (pgvector)، وده أسهل بكتير على Postgres حقيقي.
Backend مكتوب بالكامل (Express/NestJS + Postgres يدويًا)كان هيحتاج تبني Auth وStorage وREST layer بنفسك. Supabase بيديهم جاهزين، وسايب مساحة لـ Edge Functions للحالات المعقدة بس.

الفكرة العملية: أي عملية CRUD بسيطة (زي أرشفة ملاحظة) بتعدّي على PostgREST مباشرة من الواجهة، تحت حماية RLS، من غير ما تكتب سطر backend واحد. الـ Edge Functions بتتكتب بس لما محتاج مفتاح مزوّد خارجي (Anthropic/ElevenLabs/Cohere) أو منطق متعدد الخطوات.

create or replace function public.capture_note(
  p_client_id uuid, p_source public.note_source, p_language text default 'ar',
  p_raw_text text default null, p_client_created timestamptz default now()
) returns uuid language sql security invoker
as $$
  insert into public.notes (client_id, source, input_language, raw_text, client_created_at, status)
  values (p_client_id, p_source, coalesce(p_language,'ar'), nullif(btrim(p_raw_text),''),
          coalesce(p_client_created, now()),
          case when p_source = 'text' then 'queued'::note_status else 'draft'::note_status end)
  on conflict (user_id, client_id) do update set updated_at = now()  -- do update مش do nothing
  returning id;                                                       -- عشان لازم يرجّع id حتى لو موجودة
$$;

رحلة ملاحظة صوتية كاملة

  1. العميل: تسجيل → IndexedDB

    ديمومة فورية، بدون شبكة، بدون تأخير محسوس.

  2. العميل: POST /notes → note_id

    idempotent على client_id.

  3. العميل: POST /notes/audio-url → رابط موقّع

  4. العميل: رفع مباشر لـ Storage

    البايتات مبتلمسش أي Edge Function أبدًا — رفع 25MB جوه function هيستهلك ذاكرتها ويحدّد أقصى مدة تسجيل.

  5. السيرفر: POST /transcribe

    ElevenLabs Scribe → نص + درجة ثقة.

  6. السيرفر: POST /enrich

    Claude → ملخّص/تصنيف/وسوم/أولوية → Cohere → متجه 1024 بُعد → SQL → أقرب ملاحظات مشابهة.

  7. العميل: يرى الحالة ready

القرارات الثلاثة اللي شكّلت كل حاجة تانية

  • الالتقاط محلي أولًا: العميل بيكتب لـ IndexedDB قبل أي محاولة شبكة — عشان كده الـ latency هو latency التخزين مش الشبكة.
  • اللغة بتتحدد مرة واحدة، عند الحافة (edge)، وبعد كده بتتنقل صراحة لكل مرحلة تالية — ده اللي بيمنع الفشل الكلاسيكي: صوت بيتحوّل بلغة ويتلخّص بلغة تانية.
  • مفاتيح المزوّدين متسيبش السيرفر أبدًا: أي متغيّر بادئته VITE_ علني (بيتصرف جوه JavaScript أي زائر يقدر يقراه)، فمفاتيح Anthropic/ElevenLabs/Cohere عايشة بس في Edge Function secrets.

Caching — طبقتين مختلفتين تمامًا

النوعالوصف
Prompt Caching (الأهم)الـ system prompt بتاع Claude ثابت الحروف تمامًا (frozen عند تحميل الملف) ومُعلَّم بـ cache_control: {type: "ephemeral"}. النتيجة: التوكنز المخزّنة بتتحاسب على ~10٪ من سعر الإدخال العادي — توفير حوالي 60٪ على كل ملاحظة. أي متغيّر (وقت، اسم مستخدم) لو دخل جوه الـ prompt هيكسر الـ cache صامتًا، فالكود بيسجّل prompt_cache_miss لو حصل ده تحديدًا.
Service Worker cache (PWA)بيخزّن شكل التطبيق نفسه (JS/CSS/HTML) عشان يفتح أوفلاين. مايخزنش ردود الـ API عمدًا — الملاحظات عايشة في IndexedDB اللي أصلًا قابل للقراءة والكتابة أوفلاين، فكاش HTTP قديم هيغطّي على نسخة أحدث موجودة فعلًا عند المستخدم.

Rate Limiting

حد 60 استدعاء لكل مستخدم لكل مرحلة (transcribe/enrich/embed) خلال 15 دقيقة، محسوب من جدول ai_jobs نفسه (اللي أصلًا بيسجّل كل محاولة):

export async function enforceRateLimit(admin, userId, stage, noteId?) {
  const { data: hit, error } = await admin.rpc("rate_limit_hit", {
    p_user_id: userId, p_stage: stage, p_limit: 60, p_window_minutes: 15,
  });
  if (error) { console.error(...); return; }  // فشل مفتوح: خطأ قياس مايوقفش طلب شرعي
  if (hit) throw new HttpError(429, "rate_limited");
}

أمان إضافي جدير بالذكر

  • Content-Security-Policy صارم: مفيش unsafe-inline ولا unsafe-eval، مبني في vite.config.ts ويُشحن كهيدر حقيقي + <meta> احتياطي.
  • الجلسة في localStorage (ضعف حقيقي مقارنة بتطبيق أصلي بيستخدم keychain النظام) — CSP هنا مش تحسين، هي خط الدفاع الأساسي ضد سرقة الجلسة عبر XSS.
  • الحماية من Prompt Injection: طبقتين — البرومبت بيوضّح إن نص الملاحظة "بيانات مش تعليمات"، والمخرجات مقيّدة بـ schema صارم فمستحيل تخرج بشكل غير متوقّع حتى لو الحقن نجح جزئيًا.
  • لا يوجد dangerouslySetInnerHTML في أي مكوّن — React بيهرّب كل نص تلقائيًا، ونص الملاحظة (من مستخدم أو من نموذج ذكاء اصطناعي) غير موثوق بشكل متساوٍ.
